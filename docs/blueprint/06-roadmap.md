# DingClaw 实施路线图

## 目标

用分阶段方式把当前个人实验环境，升级成可管理、可控、可审计的企业级产品。

## Phase 0: 基线收敛

目标：

- 停止继续在本机安装目录里散改
- 建立私有仓和蓝图文档
- 固化企业默认安全基线

交付物：

- 私有仓初始化
- 文档体系
- 环境分层方案
- 风险清单

验收标准：

- 可以明确区分实验配置和企业配置
- 所有后续工作都在私有仓进行

## Phase 1: 企业钉钉接入

目标：

- 把现有钉钉插件升级为企业版 connector
- 稳定识别用户、群组、账号、会话

交付物：

- `dingtalk-enterprise` 插件
- 基础组织身份同步
- 群组和用户元数据缓存
- 标准化 `subjectClaims`

验收标准：

- 每条请求都能拿到统一 identity
- 可以按群、按人、按角色进行基础路由

## Phase 2: 中文管理后台

目标：

- 提供配置、组织、agent、模型、权限的中文后台

交付物：

- 后台登录
- 模型中转配置页
- agent 管理页
- 组织与群组管理页
- 策略管理页

验收标准：

- 非研发管理员也能完成基础配置

## Phase 3: 权限与审批

目标：

- 建立正式策略引擎和审批流

交付物：

- Policy Engine
- Tool 分级
- 风险规则
- 审批工单
- 审计事件中心

验收标准：

- 高风险动作不会直接执行
- 每个敏感动作都有责任人和审计记录

## Phase 4: OA / Internal API 工具化

目标：

- 把主要业务能力从聊天升级为“正式工具”

交付物：

- OA 审批工具
- 审批状态查询
- 知识库工具
- 内部系统 API 工具

验收标准：

- 主要业务流程通过 API 完成，不依赖浏览器兜底

## Phase 5: 浏览器兜底与证据链

目标：

- 对无法 API 化的系统提供受控浏览器自动化

交付物：

- Browser Worker
- 浏览器动作审批
- 截图和证据存档
- 重试和失败恢复

验收标准：

- 浏览器不是默认路径
- 浏览器动作全部可追踪、可回放、可审计

## Phase 6: 生产化与运营

目标：

- 上线试点并具备持续运营能力

交付物：

- 监控告警
- 成本统计
- 安全巡检
- 升级流程
- Runbook

验收标准：

- 支持试点部门真实使用
- 有明确值班、恢复、回滚流程

## 建议的首个实现顺序

### Sprint 1

- 建私有仓
- 导入 OpenClaw upstream
- 落地企业版目录结构
- 抽离当前 DingTalk 插件
- 固定企业默认安全策略

### Sprint 2

- 统一身份模型
- `subjectClaims` 注入
- 基础后台框架
- 模型中转配置页

### Sprint 3

- Policy Engine MVP
- agent 路由
- 工具权限
- 审计事件

### Sprint 4

- OA API 工具
- 审批流
- 审批人配置

## 里程碑定义

### M1: 可识别

系统知道“是谁在什么场景下说话”。

### M2: 可治理

系统知道“谁可以用什么”。

### M3: 可审计

系统知道“谁做了什么，为什么做，是否经过审批”。

### M4: 可上线

系统具备后台、策略、告警、回滚和运行手册。

## 当前优先级建议

当前最优先不是继续改浏览器或截图，而是：

1. 私有仓和产品骨架
2. 企业版钉钉身份层
3. 中文后台
4. 策略和审批
5. OA 工具
