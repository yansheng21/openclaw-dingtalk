# DingClaw 产品总览

## 一句话定义

DingClaw 是一个面向企业内部使用的钉钉智能助手平台，基于 OpenClaw 运行内核，具备组织身份识别、角色化响应、权限控制、审批治理、工具编排和审计能力。

## 目标问题

企业内部助手如果只做到“接钉钉消息 + 接一个大模型”，会很快遇到下面的问题：

- 无法识别说话的人是谁，只能把所有请求当匿名消息处理
- 无法按部门、岗位、权限、群组做差异化响应
- 群聊中风险过高，任何人都可能触发敏感工具
- 无法审计“谁在什么时候让机器人做了什么”
- 无法把 OA、审批、知识库、内部系统整合成正式产品
- 一旦要升级上游 OpenClaw，私改 node_modules 很难维护

## 产品目标

第一阶段目标：

- 稳定接入钉钉企业内部机器人
- 识别员工、群组、部门、角色、上下文
- 基于身份和场景切换 agent、人格、工具权限
- 提供中文管理后台
- 支持模型中转配置
- 支持审批类工具和内部 API 工具
- 对高风险动作进行审批、留痕、追踪

第二阶段目标：

- 完整 OA 工具化
- 组织知识库和多数据源接入
- 多节点执行和浏览器工作池
- 审计报表、成本统计、告警联动
- 与企业 IAM、SSO、CMDB、ITSM 深度联动

## 非目标

以下内容不作为首期目标：

- 面向公网开放的匿名聊天入口
- 默认允许机器人在宿主机任意执行命令
- 依赖浏览器自动化完成主要业务流程
- 让每个用户共享同一个无限上下文会话
- 把产品做成单纯的“聊天外壳”

## 核心原则

### 1. API First

能走正式 API 的业务一律不走浏览器自动化。  
浏览器只作为兜底工具。

### 2. Identity First

任何请求先识别“是谁、在哪、以什么身份、在什么场景下说话”，再决定如何回答。

### 3. Policy First

权限、工具、数据范围、审批规则全部由策略决定，不靠 prompt 硬编码。

### 4. Chinese Operator Experience

后台、告警、策略、审计、配置界面全部默认中文。

### 5. Secure by Default

默认白名单、默认提及触发、默认沙箱、默认审批、默认审计。

### 6. Minimal Core Patch

尽量不改 OpenClaw 核心主流程，大部分能力通过扩展点和外围服务实现。

## 用户角色

- 员工：普通使用者，查询、申请、操作类请求
- 主管：具备团队视角，可发起或查看团队相关操作
- 部门管理员：管理本部门规则、知识、可见性
- 平台管理员：管理全局模型、权限、策略、插件、节点
- 安全/审计员：查看审计日志、审批记录、敏感操作轨迹
- 运维操作员：管理执行节点、浏览器节点、故障处理

## 典型场景

- 员工在钉钉私聊中发起 OA 审批
- 员工在群里 @ 机器人查询制度和流程
- 主管请求机器人汇总团队待办和审批状态
- IT 机器人识别技术群和运维群，使用不同 agent 风格
- 高风险工具调用触发审批流，由指定管理员确认
- 机器人根据部门和身份自动切换语气、信息粒度、工具边界

## 成功标准

- 对企业用户来说，它不是“会聊天的机器人”，而是“有身份、懂边界、可审计、可治理的企业助手”
- 对平台管理员来说，权限和风险可以清楚表达、控制和追踪
- 对研发团队来说，升级 OpenClaw 不会演变成一次高风险重构
