# DingClaw 风险清单

## 目标

在真正开始实现前，把主要风险先写清楚，不等上线后再补救。

## 风险分级

- `Critical`
- `High`
- `Medium`
- `Low`

## 风险列表

### R-001: Prompt Injection 触发高风险工具

- 等级：Critical
- 场景：群聊中有人诱导机器人执行敏感操作
- 影响：越权、数据泄露、错误执行
- 缓解：
  - 默认 `allowlist`
  - 默认 @ 触发
  - 工具分级
  - 高风险动作审批
  - sandbox 默认开启

### R-002: 宿主机执行权限过宽

- 等级：Critical
- 场景：把个人实验版配置直接带到企业环境
- 影响：命令执行、文件破坏、横向风险
- 缓解：
  - 企业默认禁用 host exec
  - exec 单独审批
  - 使用专用执行节点

### R-003: 身份映射错误

- 等级：High
- 场景：钉钉 staffId 和企业 subject 映射错人
- 影响：权限错判、数据串人
- 缓解：
  - 技术身份和企业身份分离
  - 映射表可审计
  - 支持人工纠错

### R-004: 群组策略配置错误

- 等级：High
- 场景：群误设为 `open`
- 影响：任何成员都可触发敏感能力
- 缓解：
  - 企业默认 `groupPolicy=allowlist`
  - 后台风险提示
  - 高风险配置变更审批

### R-005: 浏览器自动化成为主路径

- 等级：High
- 场景：为追求快，所有业务都走浏览器
- 影响：脆弱、不稳定、难审计
- 缓解：
  - API First
  - 浏览器仅兜底
  - 浏览器任务审批

### R-006: OpenClaw Upstream 升级失控

- 等级：High
- 场景：core patch 太多，升级时大量冲突
- 影响：无法跟进上游版本
- 缓解：
  - 最小 core patch
  - 业务能力放插件和外围服务
  - patch 清单和 ADR

### R-007: 模型中转不可用或质量波动

- 等级：High
- 场景：外部中转接口抖动或返回不稳定
- 影响：用户体验下降、业务中断
- 缓解：
  - 多 route
  - provider fallback
  - 健康检查
  - 限流和熔断

### R-008: 敏感数据泄露到模型或日志

- 等级：Critical
- 场景：审批内容、员工信息、业务数据被无控制发送
- 影响：合规和隐私问题
- 缓解：
  - 数据分级
  - 日志脱敏
  - 审计
  - 模型发送前过滤

### R-009: 审批流和执行流不一致

- 等级：High
- 场景：审批通过后恢复执行失败，或执行内容与审批内容不一致
- 影响：治理失效
- 缓解：
  - 审批请求固定上下文快照
  - 恢复执行令牌
  - 执行前二次校验

### R-010: 后台配置无版本与回滚

- 等级：Medium
- 场景：管理员改坏配置且无法回退
- 影响：生产事故
- 缓解：
  - 配置版本化
  - diff
  - 回滚

### R-011: 多 Agent 之间边界不清

- 等级：Medium
- 场景：同一请求路由到错误 agent
- 影响：人格错乱、权限错用
- 缓解：
  - 明确 bindings
  - 策略测试台
  - 路由命中解释

### R-012: 审计不全

- 等级：High
- 场景：只记录聊天，不记录工具和审批
- 影响：事故后无法追查
- 缓解：
  - 所有关键事件统一写审计
  - 结构化事件模型

### R-013: 浏览器证据链缺失

- 等级：Medium
- 场景：浏览器代操作后无截图和上下文
- 影响：无法复盘
- 缓解：
  - 截图
  - 参数快照
  - 操作日志

### R-014: 组织同步延迟

- 等级：Medium
- 场景：员工离职或转岗后权限未及时更新
- 影响：越权或误拦截
- 缓解：
  - 定时同步
  - 手动刷新
  - 状态缓存 TTL

### R-015: 成本不可控

- 等级：Medium
- 场景：高推理模型被大范围调用
- 影响：费用失控
- 缓解：
  - route 限制
  - agent 默认模型分级
  - 成本报表和告警

## 当前必须先处理的风险

如果从今天开始做，最先要压掉的是：

1. R-001 Prompt Injection
2. R-002 宿主机执行权限过宽
3. R-003 身份映射错误
4. R-004 群组策略配置错误
5. R-008 敏感数据泄露

## 风险治理原则

- 默认拒绝，而不是默认开放
- 默认审计，而不是出事后补日志
- 默认 API，而不是默认浏览器
- 默认沙箱，而不是默认宿主机
- 默认最小 patch，而不是全面 fork core
